# UX-05: Seamless Progress Logic

## Goal
Eliminate "jumpy" charts and redundant animations by persisting the visual state of the MaxPanel charts. The chart should "remember" where it left off and animate only the *new* segments when the user returns to the view.

## Core Logic
1.  **State Persistence:** Introduce `visualizedTurn` (integer) state. This tracks the last turn index that has been fully animated/rendered.
2.  **Sequential Interpolation:** instead of animating from "Previous Turn" to "Current Turn" all at once, animate one turn at a time in sequence if multiple turns have passed.
3.  **Idempotency:** If `visualizedTurn === gameState.turn`, NO animation should occur. The chart should render instantly at the final state.
4.  **Base Data Integrity:** The chart always starts with the `analytics.history` (Backstory) as the immutable base.

## Implementation Details
- **Component:** `MaxPanel.tsx`
- **State:**
    - `visualizedTurn`: Tracks progress.
    - `displayData`: The array being rendered to the chart.
- **Effect:**
    - On mount or `gameState` update:
        - Check if `gameState.turn > visualizedTurn`.
        - If yes, start animation loop.
        - Tween from `currentVal` to `nextTurnVal`.
        - Upon completion, increment `visualizedTurn` and repeat if more turns exist.

## Markers
- **ReferenceLine:** Rendered for every *completed* turn in `gameState.history`.
- Keying: Must align with the X-Axis domain (e.g., `T1`, `T2`).
